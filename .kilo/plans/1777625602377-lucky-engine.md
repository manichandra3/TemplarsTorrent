# Code Review & Fix Plan

Look, I've dug through your codebase, and frankly, it's a mess. You've got Godot 3 syntax desperately trying to run in a Godot 4 engine, your architecture is duct-taped together with hardcoded paths, and you're polling for resource updates every frame like it's 1995. Let's not even talk about the duplicate code scattered across your units.

Here is the plan to salvage this project and bring it up to modern Godot 4 standards:

## 1. Fix Godot 4 Breaking Changes & Errors
Your UI code is literally going to crash because you're using Godot 3 properties.
*   **`scripts/spawner.gd`**: You're assigning `control.margin_bottom` and `control.margin_right`. The `margin_*` properties were removed in Godot 4! These must be changed to `offset_bottom` and `offset_right`. 
*   **Physics Queries**: `game.gd` uses physics queries well enough, but you're checking for `MOUSE_BUTTON_LEFT` via a raw integer check in `_unhandled_input` instead of using proper Input Actions. 

## 2. Untangle the Autoload Spaghetti
You are double-instantiating your managers, and it's causing race conditions and pathing nightmares.
*   **Duplicate Instances**: `Game` (`scripts/game.gd`) and `ResourceManager` are registered as Autoloads in `project.godot`. However, you are *also* manually instantiating them as nodes in `scenes/game.tscn`. This means you have two copies of the game logic and resources running simultaneously! We need to remove them from `game.tscn` and strictly use the globally accessible Autoloads.
*   **Brittle Paths**: `pawn.gd`, `knight.gd`, `archer.gd`, and others all use `@onready var main = get_node("/root/game")`. This is horribly brittle and will break if the scene tree changes. Since `Game` is an Autoload, they should reference the `Game` Autoload directly, rather than crawling the `/root` tree.

## 3. Stop Polling, Start Signaling
Your UI performance is crying.
*   **`scripts/resource_manager.gd`**: You just `print()` when resources change. Add proper signals: `signal wood_changed(new_amount: int)` and `signal gold_changed(new_amount: int)`. Emit these whenever resources are added or spent.
*   **`scripts/wood_label.gd` & `scripts/gold_label.gd`**: You are using `_process(delta)` to update the text *every single frame*. Delete that garbage. Connect these labels to the `ResourceManager`'s new signals in `_ready()` so they only update when values actually change.

## 4. Enforce Static Typing
Godot 4 gave us great static typing for GDScript. Use it! 
*   **`scripts/game.gd`**: Your signals are untyped (e.g., `signal entity_move_requested(entity_id, target_position)`). Update them to Godot 4 standards: `signal entity_move_requested(entity_id: int, target_position: Vector2)`.
*   Functions like `change_selected_unit(new_unit)` need proper typing (`new_unit: Node2D` or `CharacterBody2D`). This goes for return types as well (`-> void`).

## 5. Architectural Red Flags (For Future Refactoring)
I won't rewrite your whole game today, but you need to know this: `archer.gd`, `knight.gd`, `pawn.gd`, and `torch_goblin.gd` all copy-paste the exact same state machine, selection logic, damage logic, and target detection. There is ZERO inheritance or composition. In the future, extract these into a `BaseUnit` class or use components (e.g., `HealthComponent`). For now, we will focus on the fixes above to stabilize the project.

Do these fixes, and maybe the engine will stop screaming at you.
