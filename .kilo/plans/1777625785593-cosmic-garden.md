# Game Loop & Architecture Fix Plan

## 1. Decouple Player Input (Fixing the God Object)
Right now, `Game` (`scripts/game.gd`) handles player input, selection, and raycasting. We will move this into a dedicated `PlayerController` to prepare the game for multi-player, better scaling, and proper architecture.
*   **Create `scripts/player_controller.gd`**: A script attached to a new Node2D or Node inside `scenes/game.tscn`.
*   **Move `_unhandled_input`**: Take the selection raycast, movement requesting, and `change_selected_unit()` out of the `Game` Autoload and into `PlayerController`.
*   **Update UI Paths**: Ensure any direct calls to `Game.change_selected_unit` are updated to use signals or reference the `PlayerController` instead.

## 2. Optimize AI Vision (Fixing O(N) Targeting)
The `TorchGoblin` is iterating through all units in the game tree to find targets. This is a massive performance bottleneck.
*   **Update `scenes/torch_goblin.tscn`**: Add an `Area2D` named `VisionArea` as a child, with a `CollisionShape2D` (CircleShape2D) matching the `detection_radius` (e.g., 200.0).
*   **Set Collision Masks**: Ensure the `VisionArea` only scans the physics layers where Knights and Pawns reside.
*   **Update `scripts/torch_goblin.gd`**:
    *   Connect the `body_entered` and `body_exited` signals from `VisionArea`.
    *   Maintain an internal array `var enemies_in_range: Array[Node2D] = []`.
    *   Rewrite `look_for_target()` to ONLY evaluate units currently inside `enemies_in_range`, rather than querying the entire SceneTree.

## 3. Create a Base Unit System (Fixing Code Duplication)
`pawn.gd`, `knight.gd`, and `archer.gd` all replicate exact copies of movement, selection logic, and damage handling.
*   **Create `scripts/base_unit.gd`**: A new script extending `CharacterBody2D`.
*   **Consolidate Logic**: Move shared variables (`health`, `movement_speed`, `is_selected`) and core methods (`select()`, `deselect()`, `take_damage()`, `die()`) into `base_unit.gd`.
*   **Refactor Units**: Make `pawn.gd`, `knight.gd`, and `archer.gd` extend `BaseUnit` (or whatever class name we assign it) and delete the duplicate methods/variables from their respective scripts. Wait, the scripts in the game are `extends CharacterBody2D` with specific variables. We will inject `extends "res://scripts/base_unit.gd"` at the top of these files and remove duplicate functions.

This plan addresses the three core issues causing spaghetti code and poor performance.
